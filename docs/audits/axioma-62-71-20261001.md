# PRE-031 · Axioma §§62–71 · matriz de evidencia · 01/10/2026

## Alcance

Auditoría sobre `main` tras cerrar REL-049 / Financial App 10.0.49. El objetivo es distinguir evidencia objetiva, juicio visual humano y defectos funcionales reales. PRE-031 no cambia funcionalidad, datos ni versión.

## Resultado ejecutivo

No se ha encontrado un defecto funcional reproducible que justifique abrir Financial App 10.0.50. Sí existía una deuda de certificación: §§62–71 no tenían un gate transversal explícito pese a contar con múltiples implementaciones y pruebas parciales.

Se añade `scripts/audit-axioma-62-71.mjs` y el workflow `Axioma 62-71 Certification`. El gate falla si se degradan invariantes objetivas de sistema. No intenta convertir en una métrica automática cuestiones subjetivas como calma visual, densidad apropiada o pertinencia estética.

## Matriz

| Axioma | Evidencia objetiva | Estado PRE-031 | Límite / revisión humana |
| --- | --- | --- | --- |
| §62 Minimalismo financiero | tokens de espacio, superficies, bordes y radios; estructura por contenido | Objetivo protegido | La cantidad óptima de elementos y la calma visual necesitan inspección contextual |
| §63 Uso del color | tokens `primary`, `success`, `warning`, `danger`; estados reutilizables | Objetivo protegido | La pertinencia semántica de cada uso concreto requiere revisión visual/funcional |
| §64 Tipografía | escala central `--font-*`, unidades relativas/clamp, pila global única | Protegido | Revisar excepciones locales cuando se incorporen nuevas pantallas |
| §65 Iconografía | `ProductIcon` como familia interna, SVG no focalizable/oculto cuando acompaña texto, sin librería externa paralela | Protegido | Los iconos ambiguos aislados deben conservar nombre accesible/tooltips según contexto |
| §66 Densidad | responsive PRE-030: 16 tamaños, tablet propia, sin overflow, transición entre breakpoints | Evidencia previa fuerte | La densidad óptima es parcialmente subjetiva y debe validarse en pantallas con datos reales |
| §67 Navegación | `nav` nombrado, `aria-current`, skip link, feedback de transición; PRE-030 móvil/escritorio | Protegido + evidencia E2E previa | Mantener consistencia al añadir nuevas secciones |
| §68 Feedback visual | proveedor global pending/success/error, regiones live, roles status/alert, estados de carga/guardado | Protegido | Cada nueva mutación debe integrarse en este patrón |
| §69 Tablas/listados | tabla semántica, cabeceras, etiquetas móviles, filtros nombrados, responsive PRE-030 | Protegido en invariantes | Ordenación sólo es obligatoria cuando aporta valor; debe decidirse por módulo, no imponerse artificialmente |
| §70 Formularios | labels visibles, validación `aria-invalid`/`aria-describedby`, errores anunciados, guardado visible, fuente bancaria preservada | Protegido | Confirmaciones sensibles deben revisarse según impacto/reversibilidad de cada acción |
| §71 Jerarquía | H1, resumen/KPIs antes de detalle, jerarquía tipográfica central | Protegido en estructura | Prioridad visual final requiere inspección con datos reales |

## Evidencia adicional ya existente

- PRE-030 / PR #439: responsive global y tablet certificado en 16 tamaños entre 360 y 2560 px, incluida navegación móvil/escritorio y objetivos táctiles.
- `app/app-shell.tsx`: navegación principal accesible, estado de sección y transición, skip link.
- `app/action-feedback.tsx`: contrato global pending/success/error con live regions.
- `app/transactions/transactions-client.tsx`: filtros con labels, estados de carga/error, tabla semántica y formularios con validación accesible.
- `app/globals.css`: tokens semánticos de color, espaciado y jerarquía tipográfica.
- `src/design/product-icons.tsx`: lenguaje iconográfico interno único.

## Decisión de versión

**No abrir 10.0.50 por esta auditoría.** PRE-031 es hardening de evidencia sobre 10.0.49. Un próximo PATCH sólo se justifica con una mejora o discrepancia funcional real, reproducible y verificable.
