# REC-DOC-AUTH-226/227 · PATCH de revisión OCR autenticado antes de leer datos
Fecha: 19/10/2026 · PR #619 DRAFT · cambio únicamente en rama de integración, sin merge ni deploy.

## Hallazgo
El GET de `/api/documents/ocr-review` ya exigía `requireVerifiedSourceWorkspace()`, pero PATCH comenzaba por `readLimitedJsonRequest()` y la validación del documento. El gateway era el último guard de la escritura, pero una solicitud anónima podía ser procesada por el parser antes de confirmar sesión y membresía. Se corrige la precedencia para que ninguna carga OCR se lea o valide sin acceso confirmado.

## Implementación
- `app/api/documents/ocr-review/route.ts`: ejecutar `requireVerifiedSourceWorkspace()` **antes** de consumir el body de PATCH, devolver su respuesta sin leer el contenido si se deniega. Incluye sesión y acción read-only `source.capabilities` para verificar pertenencia; no se basa únicamente en presencia de cookie.
- `tests/e2e/document-api-query-guards.spec.ts`: REC-DOC-AUTH-226 hace dos solicitudes reales por HTTP sin sesión, una con JSON inválido y otra con formato correcto; ambas han de devolver 401 `authentication_required` con `cache-control: no-store` y sin ecos de datos. REC-DOC-AUTH-227 comprueba el orden guard → rechazo → parser → gateway. REC-OCR-REVIEW-055 preserva verificación del parser y mapeo a 400 sin invocar directamente la ruta fuera de un contexto de sesión Next.
- `tests/e2e/document-ocr-json-byte-limit.spec.ts`: REC-OCR-MEM-006 requiere 401 incluso para cuerpo demasiado grande anónimo; REC-OCR-MEM-007 conserva el mapeo del error `too_large` a 413 para solicitudes cuyo acceso haya sido autorizado. El límite de streaming de 256 KiB no se modifica.
