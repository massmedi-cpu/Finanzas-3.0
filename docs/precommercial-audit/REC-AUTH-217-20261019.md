# REC-AUTH-217 · Comprobar acceso anónimo en la preview exacta, sin escrituras

Fecha 19/10/2026. PR #619 DRAFT. El trabajo previo protegió GET de estado Google, salud, sync, conexión y callback OAuth. Sin embargo, las suites E2E sintéticas y las consultas a una preview mediante un enlace compartido **no constituyen** comprobación de identidad propia de Financial App: Vercel puede bloquear antes de llegar a Next.js.

Se añade `.github/workflows/protected-preview-readonly-source.yml`, automatizado para PR internas que cambien rutas o controles de Auth. Solo obtiene un OIDC efímero de GitHub, descubre una **preview exitosa vinculada al SHA exacto** mediante Deployments de GitHub, exige `/api/build.commit === head.sha` y hace exclusivamente GET anónimos a conexión Google, estado de sync, salud del runtime y comienzo de OAuth. Todos deben responder 401 `authentication_required`, sin campos de correo/archivo/datos bancarios y con `Cache-Control: no-store`. Ningún cuerpo se imprime en logs.

Se usa el mismo patrón de OIDC y descubrimiento que ya existe en Gate 4, pero **sin ejecutar** el POST de creación de cuenta de PRE-003, sin tocar base productiva, API de Google, token exchange ni backups. Forks no reciben tokens. La prueba se bloquea si falta despliegue exacto o si la puerta de Vercel no admite el token; jamás transforma ese 401 de Vercel en un éxito de Financial App.

**Limitación:** este gate no valida dos usuarios autenticados, OCR real, restauración de copias ni importación bancaria. Sigue pendiente AP1 multiworkspace, AP2 segregación cloud, AP5 conciliación segura, AP7 G5 y AP8 backup/release. No cerrar publicación por este gate.
