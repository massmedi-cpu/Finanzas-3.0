# REC-DOC-AUTH-222 a 224 · Carpeta autorizada verificada antes y después del contenido
Fecha 19/10/2026. PR #619 DRAFT. Solo código y tests sintéticos, sin modificaciones de originales.

El POST manual `/api/documents` (`action=drive_batch`) acepta `fileId` remitidos por navegador. Tras pasar el guard Auth/membership 218–220, el downloader del servicio todavía podía leer IDs que la cuenta de servicio veía en carpetas **ajenas** a la carpeta Financial App, porque no revisaba `parents` en Google Drive.

Se añade `expectedAuthorizedFolderId` opcional al downloader de documentos, únicamente requerido por el flujo manual de importación. Google Drive entrega `parents` en los metadatos; se comprueba que incluye la carpeta canónica `FINANCIAL_APP_DOCUMENTS_DRIVE_FOLDER_ID` antes de solicitar bytes. Si no, se rechaza con el error público existente de acceso. Tras la descarga se vuelven a consultar los metadatos y se rechaza una mudanza de carpeta para no guardar un snapshot que dejó de pertenecer al origen. La ruta automática ya descubre únicamente hijos de la carpeta autorizada; OCR/descarga de originales registrados no cambian.

REC-DOC-AUTH-222 comprueba 0 GET de bytes al indicar ID externo. REC-DOC-AUTH-223 prueba mudanza de carpeta entre los dos GET de metadatos. REC-DOC-AUTH-224 acepta un PDF sintético que permanece autorizado y confirma que la ruta manual pasa el folderId. Sin conexión Google, banco ni datos privados.

AP1–AP8 permanecen parciales: falta Auth multiusuario cloud real, base segregada, 20 movimientos, OCR G5 real, backup/restauración y release.
