# REC-AUTH-215/216 · OAuth Google requiere sesión y pertenencia al workspace

19/10/2026. PR #619 DRAFT. App usa service-account actualmente, pero estas rutas OAuth deben quedar protegidas ante futuras configuraciones.

## Hallazgo
`GET /api/source/google/connect` iniciaba OAuth y emitía cookie state antes de comprobar sesión propia. `GET /api/source/google/callback` podía entrar en canje del código y guardado del refresh token tras verificar únicamente el state OAuth y el correo autorizado, sin Auth Financial App ni comprobación de workspace. El state protege CSRF, pero no sustituye identidad del usuario de la aplicación.

## Corrección
Conectar exige `requireVerifiedSourceWorkspace()` antes de resolver credenciales Google o emitir redirección/cookie. En callback, los state ausentes/manipulados y errores OAuth mantienen sus redirecciones seguras; tras validar state y código, se exige de nuevo sesión/membresía por `source.capabilities` del gateway antes de acceder a credenciales, intercambiar códigos o persistir refresh tokens. Reutiliza guard ya probado de los endpoints metadata; no modifica el origen bancario, sesiones ni tokens reales.

## Pruebas de seguridad
REC-AUTH-215 solicita ruta connect SIN sesión, exige 401 y ausencia de cookie OAuth. REC-AUTH-216 presenta un state sintético válido con código falso pero sin sesión, exige 401 ANTES de cualquier intercambio. Se conservan los tests anteriores de state inválido/caducado y se incluyen las nuevas rutas en Auth Session Regression. Las solicitudes no canjean tokens, no hacen POST ni acceden a movimientos.

Este test no acredita dos usuarios Auth válidos ni OCR, AP2 cloud segregada o AP8 backup/restore. No liberar a producción hasta resto de gates.
