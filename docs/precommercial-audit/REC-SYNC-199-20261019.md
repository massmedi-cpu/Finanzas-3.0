# REC-SYNC-199 · resultado de importación con respuesta HTTP ambigua

Fecha 19/10/2026. PR #619 DRAFT. Sin escrituras reales.

## Hallazgo
Fuente bancaria `/configuration/source` presentaba el mensaje «Tus datos existentes siguen intactos» ante el fallback de un POST de sincronización que respondía con error de transporte o gateway. Esta afirmación era injustificada: una respuesta HTTP fallida puede emitirse después de que el batch transaccional se haya confirmado en PostgreSQL.

## Corrección
El fallo ambiguo ya no certifica rollback ni éxito. El mensaje explica «No se ha podido confirmar el resultado ... comprueba el último estado ... antes de repetirla». Una vez iniciado el POST, un error provoca un único refresco **GET** de estado. Nunca se repite el POST automáticamente. Preflight rechazado antes de iniciar POST no dispara el GET adicional.

## Regresión sintética
REC-SYNC-199 en `tests/e2e/source-overview-10.0.53.spec.ts`: un POST con 503 debe mostrar incertidumbre real, consultar una vez el estado registrado, no emitir segundo POST y no simular éxito. Las pruebas de sync normal, preflight y recencia permanecen. No se accede a banco ni se modifica Google o DB.

Sin acreditar AP2/AP5/AP7/AP8 ni autorizar sincronización productiva.
