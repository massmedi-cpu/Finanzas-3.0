# REC-THEME-671 · Autenticación bloquea theme-init.js y CSP impide su carga · 11/11/2026

## Evidencia en despliegue previo

- Preview Vercel candidata SHA `3856118ad3e4783aac053f01ac60ef968aa75b73`, deployment `dpl_DPBgCyUhRqETS9AYstte6UjQHSSM`, entorno `preview`, **sin tocar producción**.
- Petición GET `/theme-init.js` sin sesión: HTTP 200 pero respuesta **`text/html`**, con la pantalla «Acceso privado». La ruta está interceptada por `proxy.ts` porque su `config.matcher` omitía este recurso público, aunque excluye `sw.js` y archivos SVG.
- GET `/login`: CSP `script-src 'self' 'nonce-…' 'strict-dynamic'`. Etiqueta HTML preexistente `<script src="/theme-init.js"></script>` sin nonce. Bajo `strict-dynamic`, la lista de orígenes no autoriza esa etiqueta externa sin nonce, incluso después de corregir el matcher.
- `public/theme-init.js` sólo lee la preferencia visual `financial-app:visual-preferences-v1` de localStorage, `prefers-color-scheme` y fija `data-theme` antes de mostrar la página. No contiene datos financieros ni credenciales.
- Impacto: inicialización de tema claro/oscuro incompleta o tardía, especialmente en el acceso y al recargar, con la aplicación desplegada que exige autenticación. No se demuestra un problema de acceso a movimientos.

## Corrección en la PR #619 sin promover

1. `proxy.ts`: excluir **sólo** el recurso raíz `/theme-init.js` del middleware de autenticación. Continuar protegiendo cualquier URL privada, incluso `/theme-init.js/private`; no abrir en general la extensión `.js`.
2. `app/layout.tsx`: leer `x-nonce` inyectado por el proxy desde `next/headers` y añadirlo a la etiqueta del script. Mantener `script-src 'strict-dynamic'`, `nosniff` y la CSP actual.
3. `tests/e2e/production-auth.spec.ts`: verificar patrón de rutas públicas vs privadas.
4. `tests/e2e/content-security-policy.spec.ts`: verificar que el HTML de login aporta el nonce correcto y que el recurso devuelve JavaScript real.
