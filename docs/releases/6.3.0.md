# Financial App 6.3.0

Financial App 6.3.0 convierte la revisión documental en una bandeja universal de atención. Ya no depende de que exista un candidato de matching: también detecta OCR fallido, metadatos incompletos, ausencia de coincidencias y documentos asociados que pueden archivarse.

## Cambios principales

- Nuevo triage documental server-side y explicable para todos los documentos activos.
- Prioridad canónica: OCR fallido, metadatos incompletos, asociación segura, matching manual, ausencia de candidato y archivado.
- Las razones de prioridad se devuelven junto al documento y son visibles en la interfaz.
- El triage reutiliza el motor de matching 6.2 y consulta la política supervisada activa para evaluar ambigüedad; no mantiene un margen duplicado en React o SQL paralelo.
- La antigua cola matching-only de `/archivo/revision` se sustituye por `Atención documental`.
- Un documento con OCR fallido o datos incompletos permanece visible aunque no pueda producir candidatos.
- Desde la bandeja se puede abrir el original, abrir el documento en Archivo, asociar candidatos y archivar un documento ya resuelto, siempre mediante una acción explícita.
- El triage es de solo lectura durante su cálculo y no ejecuta OCR, asociaciones, correcciones ni archivado automáticamente.
- El RPC público está restringido a `authenticated`; `anon` no tiene permiso de ejecución.
- La nueva superficie visual entra en el gate global de 14 px mínimo y controles críticos de 44 px.
- Validación mediante GitHub CI y publicación únicamente desde `main`, sin preview intermedia.
