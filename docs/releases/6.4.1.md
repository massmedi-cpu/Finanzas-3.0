# Financial App 6.4.1

## Objetivo

6.4.1 es un parche de **hardening medido** sobre 6.4.0. No añade un motor nuevo ni cambia decisiones financieras. Cierra una deuda de rendimiento detectada por el Performance Advisor de Supabase y alinea la documentación canónica con el modelo de seguridad y publicación que ya está en producción.

## Base de datos

- Se añade un índice B-tree sobre `financial_app.document_matching_policies(supersedes_policy_id)`.
- El índice cubre la foreign key `document_matching_policies_supersedes_policy_id_fkey` y prepara el historial de políticas para sustituciones y rollback sin escaneos innecesarios al crecer.
- La migración es idempotente y no modifica movimientos, documentos ni valores de las políticas de matching.
- No se eliminan índices por el mero hecho de que el advisor los marque como todavía no usados: eso requerirá evidencia separada.

## Seguridad y arquitectura

- `anon` continúa sin acceso a operaciones financieras privilegiadas.
- Los wrappers públicos necesarios pueden usar `SECURITY INVOKER`; los cores privilegiados permanecen fuera del API público y requieren autorización explícita mediante `authorized_email()` y permisos mínimos.
- El navegador nunca recibe `service_role` ni secretos privados.
- Se corrige la documentación histórica que todavía exigía previews automáticas, aunque desde Financial App 6.0 la publicación canónica se realiza desde una rama validada hacia `main`, con Vercel desplegando únicamente producción y con smoke exacto posterior.

## Release

- `APP_VERSION` pasa a 6.4.1.
- La versión técnica npm permanece en 3.4.8.
- La base 6.4.0 acepta primero el índice compatible; solo después de CI, despliegue READY y smoke se alinean `app_version` y `target_version` a 6.4.1.
