# Financial App 6.4.0

## Salto de producto

6.4 convierte `Atención documental` en un **Centro de operaciones documentales**. La aplicación deja de limitarse a ordenar una cola: distingue qué puede resolverse con seguridad en ese momento, permite seleccionar varias acciones y las vuelve a validar en servidor justo antes de ejecutarlas.

## Operaciones seguras

- Asociación de documentos únicamente cuando el mejor candidato sigue siendo `autoEligible` según la política supervisada activa.
- Archivado únicamente cuando el documento sigue teniendo una asociación y continúa en estado resoluble.
- Selección múltiple limitada a operaciones que el servidor marca explícitamente como seguras.
- Máximo de 50 operaciones por lote.
- Cada elemento del lote se ejecuta de forma aislada: si uno deja de ser seguro, se rechaza sin invalidar los demás.
- Ningún caso ambiguo, OCR fallido, metadato incompleto o matching manual entra en el lote.

## Seguridad y reversibilidad

- Toda ejecución requiere selección y confirmación explícitas del usuario.
- Antes de escribir, el servidor debe revalidar cada operación; la UI no decide si una acción sigue siendo válida.
- La seguridad se recalcula al ejecutar; la UI no decide si una operación sigue siendo válida.
- Las asociaciones reutilizan `archive_link_calibrated_core`, por lo que conservan el historial de calibración ya validado en 6.1–6.2.
- Los archivados registran `document_history` y son recuperables con el flujo canónico de restore.
- La última tanda aplicada puede deshacerse desde la propia superficie: unlink para asociaciones y restore para archivados.
- `anon` no puede ejecutar ni wrappers ni cores. Los wrappers del esquema `public` son `SECURITY INVOKER`; los cores `SECURITY DEFINER` viven fuera del API público, son ejecutables por `authenticated` y vuelven a comprobar `authorized_email()` contra la allowlist antes de leer o escribir.
- El asesor de seguridad de Supabase no introduce ningún warning nuevo por las funciones 6.4 después de este endurecimiento.

## UX

- Nuevo resumen operativo: seguras ahora, asociar, archivar y revisión manual.
- Barra de acciones en lote con selección segura, limpieza, aplicación y deshacer.
- Cada documento seguro muestra checkbox y explicación de la operación propuesta.
- Los candidatos manuales continúan visibles y conservan su asociación explícita individual.
- Se elimina el camino roto que intentaba archivar enviando `action` en el body a un endpoint que esperaba query string.

## Arquitectura

6.4 no crea un segundo motor de matching ni un segundo triage. `document_triage_core` sigue siendo la fuente de prioridad y `document_match_candidates_rows_core` + la política supervisada siguen siendo la fuente de seguridad. La nueva capa solo orquesta acciones sobre esos contratos y vuelve a validarlos en el instante de escritura.

## Release

El contrato 6.4 se instala primero de forma compatible sobre una base 6.3.2. Después de pasar CI y publicar el runtime, la migración de release alinea `app_version` y `target_version` a 6.4.0. El paquete npm conserva por contrato su versión técnica 3.4.8.
