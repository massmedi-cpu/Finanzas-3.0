# Financial App 6.4.3

## Objetivo

6.4.3 endurece el proceso de publicación después de detectar un falso negativo real en Production Smoke durante la propagación de Vercel. No cambia cálculos financieros, movimientos, documentos, OCR, matching ni UX de usuario.

## Production Smoke

- El smoke deja de considerar suficiente que únicamente `/login` haya alcanzado la versión nueva.
- Antes de validar, exige coherencia de versión sobre login, seis rutas privadas y cinco APIs protegidas.
- La propagación se considera estable únicamente tras dos pasadas consecutivas correctas.
- Se envía `Cache-Control: no-cache` para reducir respuestas edge obsoletas durante la transición.
- Una mezcla temporal de versiones entre rutas se trata como propagación pendiente y se reintenta dentro de una ventana acotada.
- Si la coherencia global no llega dentro del límite, el workflow falla y mantiene visible el problema.
- Después de la espera global se conservan las verificaciones finales exactas de redirects y frontera API.

## Gates históricos

- Los gates 6.4.0, 6.4.1 y 6.4.2 dejan de enumerar manualmente cada patch futuro.
- 6.4.0 acepta la familia `6.4.x`.
- 6.4.1 exige `6.4.x` con patch >= 1.
- 6.4.2 exige `6.4.x` con patch >= 2.
- Cada gate sigue comprobando todos sus contratos originales; solo cambia la condición que determina si una release posterior de la misma familia puede preservar esa baseline.

## Alcance

- Cero cambios en datos financieros.
- Cero cambios de esquema funcional en Supabase.
- Cero previews de Vercel.
- La versión técnica npm permanece en 3.4.8.
- La metadata de Supabase solo se alinea a 6.4.3 después de CI verde, deployment READY y comprobación de producción.
