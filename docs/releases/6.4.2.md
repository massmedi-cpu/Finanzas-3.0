# Financial App 6.4.2

## Objetivo

6.4.2 elimina una elevación de privilegios innecesaria en la frontera pública del dashboard de calidad de matching detectada por el Security Advisor de Supabase. No cambia cálculos, movimientos, documentos, políticas ni métricas almacenadas.

## Seguridad

- `public.financial_app_document_matching_dashboard(integer,integer)` pasa de `SECURITY DEFINER` a `SECURITY INVOKER`.
- `anon` continúa sin permiso de ejecución sobre wrapper ni core.
- `authenticated` conserva `EXECUTE` sobre el wrapper y recibe únicamente el permiso mínimo necesario para ejecutar `financial_app.document_matching_dashboard_core(integer,integer)`.
- El core permanece en el esquema privado `financial_app`, continúa como `SECURITY DEFINER`, mantiene `search_path` cerrado y vuelve a comprobar `authorized_email()` antes de leer o escribir.
- La operación y el histórico de calidad se conservan sin cambios funcionales.

## Alcance

- No se elimina la función aunque no tenga referencias runtime directas: conserva compatibilidad con el contrato histórico de observabilidad.
- No se modifica ninguna tabla financiera ni dato documental.
- No se toca el warning de `trayectos_clio_protect_valid_photo_match`, que pertenece a otro producto.
- La protección de contraseñas filtradas de Supabase Auth queda fuera de este parche porque Financial App utiliza Google OAuth; cualquier cambio de proveedor de autenticación requiere un análisis separado.

## Release

- `APP_VERSION` pasa a 6.4.2.
- La versión técnica npm permanece en 3.4.8.
- La migración de seguridad se instala de forma compatible sobre 6.4.1; la metadata se alinea a 6.4.2 únicamente después de CI verde, deployment READY y verificación de producción.
