# V2.6.0 — Reglas privadas de clasificación

## Propósito

Reducir trabajo repetitivo sin sacrificar control, trazabilidad ni reversibilidad.

## Principios

- La fuente bancaria original es inmutable.
- Una regla nunca genera escrituras masivas sobre movimientos.
- Una edición manual gana por campo a cualquier regla.
- Un split explícito conserva su categoría propia.
- Solo una regla gana por movimiento: prioridad descendente y desempate estable.
- Crear/editar una regla desde la interfaz exige una vista previa vigente del formulario actual.
- Pausar o eliminar revierte inmediatamente el efecto automático.

## Flujo de usuario

1. Crear o editar una regla.
2. Elegir dónde buscar: comercio, concepto o ambos.
3. Elegir coincidencia: contiene, exacta o empieza por.
4. Restringir opcionalmente por cuenta y por dirección ingreso/gasto.
5. Definir categoría, subcategoría y/o merchant normalizado.
6. Previsualizar coincidencias, cambios y filas protegidas manualmente.
7. Solo entonces se habilita Guardar.

Cualquier modificación del formulario invalida la vista previa anterior.

## Arquitectura

`source transaction → best private rule → manual override → split` se materializa en la salida con precedencia efectiva:

`split > manual override > rule > source`.

La capa SQL `finance_v260_transaction_rows` es la fuente efectiva para Movimientos y `finance_v220_effective_rows` para analítica.

## Seguridad

- tablas RLS sin policies directas;
- acceso directo `anon/authenticated` revocado;
- Edge Function privada `finanzas-v3-rules`;
- sesión privada reenviada solo desde servidor;
- `service_role` permanece dentro de Supabase;
- match modes limitados; no se acepta regex arbitraria.

## Auditoría

`finance_v3_classification_rule_events` registra create/update/enable/disable/delete con snapshots suficientes para reconstruir qué cambió.

## Rendimiento

Las reglas se seleccionan en PostgreSQL mediante un único lateral lookup por movimiento y prioridad indexada. La paginación sigue limitada a 200 filas por API y 100 por interfaz.
