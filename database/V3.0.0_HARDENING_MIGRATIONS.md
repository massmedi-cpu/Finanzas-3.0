# V3.0.0 — Hardening de base de datos

## Migración aplicada
`finance_v300_rule_event_fk_index`

```sql
create index if not exists finance_v3_classification_rule_events_rule_id_idx
  on public.finance_v3_classification_rule_events(rule_id);
```

## Motivo
El asesor de rendimiento de Supabase detectó la FK `finance_v3_classification_rule_events_rule_id_fkey` sin índice de cobertura. V3.0 añade el índice sin modificar datos ni semántica financiera.

## Seguridad
No se añaden políticas de acceso directo. Las tablas `finance_v3_*` continúan con RLS deny-by-default y sin permisos directos para `anon`/`authenticated` cuando la arquitectura requiere acceso exclusivo de backend.

## Edge Functions endurecidas
- `finanzas-v3-data` → V3 ACTIVE.
- `finanzas-v3-recurring` → V2 ACTIVE.
- `finanzas-v3-splits` → V2 ACTIVE.

Las tres usan autorización fail-closed y mantienen el contrato funcional previo.
