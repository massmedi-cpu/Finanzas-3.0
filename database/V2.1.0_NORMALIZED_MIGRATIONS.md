# Supabase — migraciones V2.1.0 normalizadas

Este archivo documenta el orden canónico de las migraciones aplicadas en Supabase para V2.1.0. Las sentencias exactas quedan registradas en `supabase_migrations.schema_migrations` del proyecto y el esquema final se valida mediante CI/documentación antes de promover la versión.

| Versión | Migración | Propósito |
|---|---|---|
| 20260821043503 | `finance_v210_normalized_foundation` | Principal financiero interno, desacoplo de `auth.users`, columnas normalizadas, índices, sincronización inicial y consulta paginada. |
| 20260821043619 | `finance_v210_harden_extensions` | Mueve `pg_trgm` a `extensions` y mantiene acceso cliente cerrado. |
| 20260821043757 | `finance_v210_query_surface` | Estado normalizado y superficie paginada efectiva con overrides/splits/filtros. |
| 20260821044949 | `finance_v210_financial_summary` | Resumen financiero compacto de transición. |
| 20260821050136 | `finance_v210_summary_effective_overlay` | Corrige el resumen para aplicar exclusiones y estado de revisión del overlay privado. |

## Objetos V2.1.0 canónicos

- `public.finance_principals`
- `public.finance_v210_sync_current_snapshot(text)`
- `public.finance_v210_state(text)`
- `public.finance_v210_transactions_page(...)`
- `public.finance_v210_summary(text,text)`
- Edge Function `finanzas-v3-normalized` V3

## Modelo de identidad

`finance_principals` es el propietario de las tablas normalizadas. `auth_user_id` es opcional y permite enlazar Supabase Auth en el futuro, pero V2.1.0 conserva la sesión privada existente. No se crean usuarios ficticios.

## Invariantes

1. `finance_v3_current` y `finance_v3_snapshots` siguen siendo fuente/procedencia y rollback.
2. El XLSX original nunca se modifica.
3. Las tablas normalizadas se pueden reconstruir desde el snapshot mediante `finance_v210_sync_current_snapshot`.
4. Una segunda sincronización sin cambios debe producir 0 insertados, 0 actualizados y todos los movimientos sin cambios.
5. `currentChecksum == normalizedChecksum` y `currentRows == normalizedRows` son condición para mostrar datos normalizados.
6. RPC V2.1 no son ejecutables por `anon` ni `authenticated`; solo `service_role`.
7. El histórico sin cuenta explícita se conserva con la clave técnica `__historical_unassigned__`, que nunca se presenta como una cuenta real al usuario.

## Evidencia de corte V2.1.0

- 3.135 movimientos fuente = 3.135 normalizados.
- Checksum idéntico: `4039380ca155e910a05532e0c9ff7c2c6e0b1ba74b48f5732173e519e4597894`.
- 0 diferencias mensuales en la comparación fuente vs normalizado.
- Paginas keyset consecutivas sin solapamientos.
- Consulta de página de referencia: ~14 ms dentro de PostgreSQL con el dataset actual.

Para inspeccionar el SQL exacto aplicado en una auditoría de entorno: consultar `supabase_migrations.schema_migrations` por las cinco versiones anteriores; no editar retrospectivamente la historia de migraciones de producción.
