# V2.2.0 — migraciones del motor analítico normalizado

## Objetivo

Eliminar la necesidad de cargar el snapshot JSON completo en las superficies analíticas principales, manteniendo intactas la fuente bancaria y la capa privada V3.

## Migraciones aplicadas

### `finance_v220_analytics_core`

Crea funciones `SECURITY DEFINER` con `search_path = ''` y acceso exclusivo de `service_role`:

- `finance_v220_effective_rows(text, boolean)`
  - parte de `finance_source_transactions` normalizada;
  - aplica `finance_v3_movement_overrides`;
  - excluye `excluded_from_analytics`;
  - conserva la semántica de traspasos del motor TypeScript;
  - cuando se solicita, sustituye movimientos divididos por sus líneas de `finance_v3_movement_splits`;
  - mantiene `base_source_id` para que una división siga contando como una sola operación cuando corresponde.
- `finance_v220_reports(text, text)`
  - años disponibles;
  - mensual, trimestral y anual;
  - cash flow y tasa de ahorro;
  - top de categorías;
  - comparación con el año anterior hasta el mismo mes;
  - número de movimientos divididos aplicados.
- `finance_v220_budget(text, text)`
  - meses disponibles;
  - ingreso mensual;
  - gasto efectivo por categoría;
  - número de imputaciones;
  - presupuesto asignado, rollover y remanente del mes anterior.

### `finance_v220_quality_review`

Crea `finance_v220_review(text)` con acceso exclusivo de `service_role`:

- duplicados por fecha + cuenta + importe + concepto, igual que el motor previo;
- pendientes de revisión;
- movimientos sin categoría, excluyendo traspasos;
- importes atípicos por cuenta con mediana y umbral `max(500, mediana × 6)`;
- respeta resoluciones y exclusiones privadas;
- devuelve las operaciones necesarias para que `ReviewCenter` conserve sus acciones reversibles.

### `v220_recurring_patterns_sql`

Añade `unaccent` dentro del esquema `extensions` y crea:

- `finance_v220_normalize_text(text)`, usada únicamente por el backend analítico;
- `finance_v220_recurring_patterns(text)`, que replica la detección mensual del motor TypeScript sin transferir el histórico a Next.js:
  - misma clave dirección + cuenta + descripción normalizada;
  - mínimo 3 ocurrencias;
  - mediana de intervalos;
  - intervalo aceptado entre 20 y 40 días;
  - media de importe;
  - estabilidad de importe e intervalo;
  - misma fórmula de confianza con tope 0,99.

En el dataset actual devuelve 22 patrones a partir de 2.745 operaciones elegibles, evitando transportar 2.425 filas que pertenecen a grupos repetidos.

### `v220_forecast_inputs`

Crea `finance_v220_forecast_inputs(text)` para servir únicamente:

- última fecha disponible;
- patrones recurrentes calculados en PostgreSQL;
- categorías efectivas.

La Edge Function `finanzas-v3-analytics` V2 combina ese resultado con el estado normalizado ya autenticado. `Previsión` conserva en TypeScript la aplicación de preferencias, eventos planificados, escenarios y cálculo de liquidez, pero deja de cargar el snapshot completo.

### `v220_plan_core_and_net_worth`

Crea:

- `finance_v220_net_worth_history(text, int)`
  - reproduce el cierre mensual usando el último saldo conocido por identificador/cuenta;
  - respeta el orden de origen cuando hay varios movimientos el mismo día;
  - devuelve patrimonio, número de cuentas y variación mensual.
- `finance_v220_plan_core(text, text)`
  - mes seleccionado y anterior;
  - ingresos, gastos, cash flow y número de movimientos;
  - pendientes de revisión;
  - grupos de duplicados no resueltos;
  - 18 meses de patrimonio.

La Edge Function analítica V3 añade `/plan`, que ejecuta en paralelo presupuesto, núcleo del plan y entradas de previsión, reutilizando el estado normalizado ya autenticado. `Plan` conserva su lógica de insights, objetivos, escenarios y representación visual sin descargar el histórico completo.

## Seguridad

Tras crear cada función se ejecutó el equivalente a:

```sql
revoke all on function ... from public, anon, authenticated;
grant execute on function ... to service_role;
```

El Data API público no es el canal de acceso. Next.js usa la Edge Function `finanzas-v3-analytics`, que primero exige una sesión privada válida y un modelo normalizado sincronizado.

Los advisors de Supabase posteriores a la migración no muestran avisos de seguridad nuevos para `finance_v220_*`. Los avisos informativos de RLS sin políticas en `finance_v3_*` representan el diseño de denegación directa deliberado.

## Prueba de equivalencia independiente

La ruta nueva se comparó contra una segunda consulta que parte directamente de `finance_v3_current.payload.rows`, aplica los overlays y splits de V3 y no usa `finance_source_transactions` para calcular los resultados de control.

Resultado validado para 2026 / agosto de 2026:

| Métrica | Snapshot original | Motor V2.2.0 |
|---|---:|---:|
| Movimientos 2026 | 286 | 286 |
| Traspasos excluidos | 21 | 21 |
| Ingresos 2026 | 11.303,83 € | 11.303,83 € |
| Gastos 2026 | 9.749,05 € | 9.749,05 € |
| Ingresos 2026-08 | 20,73 € | 20,73 € |
| Gastos 2026-08 | 728,31 € | 728,31 € |

Resultado: `equal = true`.

El núcleo de Plan devuelve además para agosto de 2026 los mismos 20,73 € de ingresos, 728,31 € de gastos y -707,58 € de cash flow. El salto patrimonial de enero de 2026 a ~185.000 € fue auditado contra la fuente y procede de un saldo real de 181.027,33 € asociado al identificador `****2504`; no es una anomalía introducida por la normalización.

## Control de consumo de Vercel

Durante el desarrollo de V2.2.0 la rama `develop/v2.2.0-analytics` tiene desactivados los despliegues Git automáticos mediante `vercel.json`. GitHub Actions sigue ejecutando invariantes, regresiones, TypeScript, build y smoke sobre cada commit, mientras Vercel se reserva para un único preview final del HEAD de release y su posterior promoción.

## Compatibilidad y rollback

- `finance_v3_current` no se elimina ni se modifica por estas lecturas.
- Los overrides, presupuestos y splits siguen en sus tablas V3 existentes.
- V2.1.0 continúa siendo una base funcional independiente del nuevo endpoint analítico.
- La Edge Function analítica está separada de `finanzas-v3-normalized`, de modo que puede retirarse sin alterar el data plane de V2.1.0.
