# V2.5.0 — Cierre mensual y trazabilidad

## Objetivo

Añadir un cierre mensual auditable sin modificar la fuente bancaria original ni duplicar la lógica financiera.

## Objetos de base de datos

### `finance_v3_month_closures`
Estado vigente de cada periodo (`open` / `closed`), fechas de cierre/reapertura, nota y fotografía JSON de las métricas que justificaron el cierre.

### `finance_v3_month_closure_events`
Historial append-only de acciones `close` / `reopen`. Reabrir un periodo no borra el cierre anterior.

### `finance_v250_month_close_summary(year_month, principal_key)`
Resume el periodo sobre `finance_v220_effective_rows(..., false)` para mantener las mismas reglas de:
- overrides privados;
- exclusiones de analytics;
- revisión;
- conciliación;
- traspasos internos.

Devuelve movimientos, pendientes, no conciliados, sin categoría, traspasos, ingresos, gastos y cash flow.

## Seguridad

- RLS activado en las tablas nuevas.
- Sin policies para `anon`/`authenticated`: acceso directo denegado.
- RPC revocado para `PUBLIC`, `anon` y `authenticated`.
- `service_role` es el único rol con acceso directo.
- La Edge Function `finanzas-v3-closure` valida la sesión privada existente y falla cerrado (`response.ok`).

## Reversibilidad

La migración es aditiva. Ninguna ruta anterior depende de estas tablas/RPC hasta que V2.5 sea promovida. El rollback de aplicación no requiere borrar datos de cierres.
